# 독립 가상환경 비교 결과

이번 작은 과제 예비 비교에서 파생본의 전체 작업 토큰 변화는 **80.1%**, 평균 시간 변화는 **12.7%**였다. 판단만 비교하면 전체 토큰 변화는 **3.0%**, 비캐시 입력 변화는 **-37.6%**였다. 두 층 모두 각 조건의 16회 관측 검사를 통과했다.

전체 작업의 증가분은 파생본만 부모와 두 자식으로 분업한 06-discovery 유형에 집중됐다. 계산 밖의 계획·호출·통합·재검증 비용도 포함된 수치다. 모든 작업이 일률적으로 같은 비율만큼 증가한다는 뜻으로 해석할 수 없다. 판단 시험에서는 helper 호출 후 상세 출력과 내부 코드 추가 확인도 관측됐다. **중간 판단의 비캐시 입력 감소가 전체 작업의 토큰 절감으로 이어지지는 않았다.** 캐시 과금과 출력 단가가 달라 실제 청구액은 별도 측정이 필요하다.

측정일: 2026-09-23. 원본 A와 파생본 B를 각각 새 Docker 컨테이너에서 실행했다. 실제 작업 32회와 동일 상태 판단 32회를 별도로 집계한다. 사전 로그인·실행 점검과 리허설은 효과 집계에서 제외했다.

## 실제로 사용된 기능과 검증 흔적

- 전체 과제의 자식 실행 발생: A 0/16회, B 2/16회.
- B의 전체 과제에서 schedule 실행이 관측된 횟수: 2/16회. structure 실행: 1/16회. 이는 실제 명령 로그를 읽은 별도 감사다.
- 종료 산출물의 Gate 흔적: 미충족 0개, abandon 0개, 파싱 오류 0개. 이는 외부 기능 검사와 구분한다. Gate가 적혔다는 사실만으로 품질을 증명하지 않는다.
- 최종 환경 회귀: A 188/188, B 268/268. 초기 init 없는 컨테이너에서 프로세스 회수 검사가 실패하여, init을 활성화한 최종 공통 환경에서 재검증했다. 이는 사전 환경 점검이며 A/B 생산성 실패로 집계하지 않았다.

## 조건과 한계

- A: unlazy 2.1.0 출발 커밋 16671491f6679ad9378f52604d3bc2415b4120c7. B: 미커밋 변경을 포함해 동결한 Task 2~4 구현. 설치된 다른 unlazy 버전이나 이동하는 최신판과의 비교가 아니다.
- CLI 0.155.0-alpha.9.2, 모델 gpt-6-astra, low reasoning, CPU 2·메모리 3 GiB, 매회 새 환경. AB/BA 순서는 두 번째 반복에서 반전했다. 조건들을 동시에 실행해 자원을 경쟁시키지 않았다. 모델 서비스의 내부 가중치 버전까지 동결할 수 있다는 뜻은 아니다.
- 회당 실제 작업 300초/200만 토큰, 판단 150초/100만 토큰 상한. 토큰 한도는 기록 관측 후 적용되므로 진행 중 요청의 초과량이 포함될 수 있다.

- 전체 작업은 작은 Node 패키지들이다. 실제 웹사이트 전체 개발, 깊은 재귀 분업, 실행 중 강제 종료·외부 부작용의 exactly-once를 검증한 결과가 아니다. 과제 06의 분할은 자연 발생 여부를 관측했고, 과제 08은 정적 미완성 상태에서 재개했다.

- 유형당 과제 하나와 두 번의 반복인 예비 비교다. 성공률 동등성·모든 복잡한 작업에 대한 절감률을 입증하지 않는다. 기능 검사 통과와 과제 전반의 완벽한 품질을 동일시하지 않는다.
