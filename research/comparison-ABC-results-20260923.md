## C에 실제 적용한 변경

- 작업자는 필요한 개발 테스트를 하고, 공식 수락은 부모 측 검사기가 수행하도록 절차를 변경했다. Solo는 같은 에이전트가 driver 역할을 수행한다.
- 닫힌 입력 범위·관련 환경·검사기·Gate/수동 증거·scoped 계약 개정을 기록한다. 동일한 현재 증거가 있으면 재실행하지 않고 감사한다. 바뀌거나 미완료인 증거는 배정을 차단한다.
- 상위의 무조건적 자식 재검사 대신 현재 증거 감사와 실제 통합 검사를 사용한다. 참조/내부 코드 읽기와 배정 상세 출력은 필요할 때만 수행한다.
- 닫힌 입력은 작성자의 명시적 선언이며 자동 추출/증명이 아니다. 외부 상태·동시 쓰기를 보장하지 못하면 재사용하지 않는다. 영속 영수증은 적대적 변조 방지 서명이 아니다.
- 모든 native 호출을 대신하는 advance 실행기, OS 정지 자동 증명, 실제 자동 Claude Stop hook은 구현/측정 범위 밖이다. 단계별 host 조작은 남아 있다.

## 검증 범위와 해석

- 사전 Linux 회귀: 새 경로 14개를 포함한 전체 회귀 로그를 보존했다. 모델의 기능 검사 합격은 품질 동등성이나 숨은 결함 부재를 뜻하지 않는다.
- 기존과 같은 기능 합격/종료 기준으로 비교했다. 새 receipt 감사는 C 추가 진단이며 A/B의 기존 합격 기준을 사후 변경하지 않았다.
- C는 더 나중에 실행됐다. 서비스 부하·캐시·모델 비결정성·고정할 수 없는 서버 측 변경은 남는다. 유형당 2회여서 일반적 절감률이나 통계적 우월성을 주장하지 않는다.
- 전체 작업의 배정 전략과 자식 수가 다를 수 있다. 판단 구간은 입력을 동일하게 제공하지만 스킬 읽기·명령·출력 해석을 포함한다. 조정 스크립트만의 순수 계산 비용은 아니다.
- 토큰은 부모와 자식의 고유 세션별 마지막 누적 사용량을 합산한다. 캐시 입력과 reasoning 출력은 부분집합이므로 중복 가산하지 않는다. 청구액은 계산하지 않았다.
- 의미적인 검토 축소의 효과와 위험을 분리하려면 숨겨진 결함·재작업·후속 변경 시험이 필요하다. 이번 요청에 따라 기존 시험을 그대로 재사용했다.

C 패키지 해시: `e3b205eba990de25c6123dbb872e09dba2976ca61681c0b2f7e8c89babe5e519`. 기존 원자료와 동결 파일, 실행 코드·프롬프트·채점기 해시를 재검산했다. CSV는 A/B/C 모든 96개 실행 요약, JSON은 실행·감사 상세다. 원래 A/B 보고서와 데이터는 그대로 남아 있다.

사후 감사 환경 점검: 기본 Docker PATH와 Codex 도구의 PATH가 달라 첫 감사가 거부됐다. 실제 실행 로그의 PATH 중 각 과제 Gate 지문과 일치하는 값을 같은 이미지에 재현한 뒤 전체 증거 맥락을 감사했다. 과제/receipt/동결본/원래 채점 결과는 수정하지 않았다. 상세는 재현 자료의 audit-environment-check.md에 있다.
