# Task 3 설계 및 구현 검증

기준 배정 테스트 19/19를 먼저 확인한 뒤 task_3.md의 5단계 계획에 따라 구현했다. 새 스킬을 만들지 않고 기존 스킬의 판단·검증 시점에 호출을 추가했다.

구현 파일은 structure.mjs(plan/apply/recover), structure-check.mjs(읽기 전용 검산), 해당 lib 모듈과 기존 schedule helper의 registry 연동이다. Gate·dispatch·Stop hook 원본 구현은 변경하지 않았다.

## 검산 계약

계산기는 위상 정렬 기반 조상 집합으로 의존관계를 계산한다. 별도 검산기는 BFS 도달 가능성을 계산하고 작업 ID 보존, 정확히 한 그룹 배정, 필수 간선/Gate 보존, 비순환 축약, 남은 작업의 순차성, 실제 선택 후보의 독립성·용량·lease를 검사한다. 전이 검산은 변경 전 snapshot과 비교해 원래 Gate·접근 선언의 변경을 검출한다.

## 멱등 계약

동일 operation ID + 동일 payload는 한 번만 반영한다. 중복 apply와 동시 동일 요청은 파일을 다시 쓰거나 자식을 다시 생성하지 않는다. 파일 변경은 before/after journal로 복구하며 변경 대상 이외의 관측 파일도 보존한다. 준비 직후와 모든 개별 쓰기 직후에 예외를 주입해 반복 복구를 검증했다. 외부 편집·dispatch/lease 변경은 덮어쓰지 않고 중단한다.

## 검증 범위와 한계

새 테스트는 재귀 2단 분할, 별도 이벤트의 자식 분할, 합류 후 새 분할, 병합 고정점, 고아/중복/간선 누락/축약 순환/조기 부모 완료, CLI 읽기 전용, Stop hook 차단과 실제 Gate 실행 연동을 포함한다. 4노드 전방 DAG 64개와 유효한 완료 집합 조합에서 보존·고정점을 확인한다.

이미 dispatch된 부모 자동 변환은 미지원이며 거절한다. 강제 프로세스 종료로 남은 기존 filelock은 소유자 확인 후 정리해야 한다. 테스트의 중단은 예외 주입이며 전원 차단이나 자동 잠금 인계를 검증한 것이 아니다. 외부 변경을 추적하는 영구적인 증거 바인딩이나 무조건적인 종료 보장은 없다. 전체 토큰 절감은 실사용 측정 전이다.
