# Task 6 — 첫 반복과 판단 시험 사전 검산

첫 반복의 16회 실행은 외부 기능 검사와 관측된 모델 세션 종료 조건을 모두 통과했다. 이것은 전체 실험의 최종 결론이 아니다. 원본/파생본의 순서를 바꾼 두 번째 반복이 진행 중이다.

대부분의 작은 과제에서 두 스킬은 Solo를 택했다. 파생본의 manifest 요구사항 발견 과제 한 실행에서는 실제 두 자식 에이전트와 schedule/structure 호출이 발생했다. 이 실행은 981543 토큰, 219.691초였고, 같은 과제의 원본 Solo 실행은 137625 토큰, 93.926초였다. 이 한 쌍을 스크립트 계산 자체의 비용 차이로 해석하지 않는다. 전체 전략 선택과 초기 문서/상태 생성 비용이 함께 달랐다.

후속 판단 전용 시험은 전체 과제와 별도로 8개 상태 × 두 조건 × 2회로 준비했다. 상태 크기는 1~32개 작업이다. 순차/폭넓은 분기/rolling/통합 후 재분기/유지된 부모/공유 자원 충돌/계획에서 빠진 ledger를 포함한다.

모델 시험 전에 결정론적 helper 출력이 독립된 허용 배정 검사에 맞는지 확인했다. 동일 입력 두 번의 결과는 같았고, 존재하지 않는 작업·불필요한 전체 유휴·읽기/쓰기 충돌 배정은 거부했다. planned wave가 선행 작업보다 앞설 수 없다는 입력 조건과 진행 중 native dispatch 기록도 사전에 확인했다.

두 조건 모두 같은 사실 파일에 접근한다. 파생본이 helper로 파일을 읽고 검산한 경우 LLM에게 같은 파일 전체를 다시 읽게 강제하지 않는다. 준비된 사실을 처음 발견하는 비용은 판단 시험에서 제외하며 전체 과제 시험과 혼동하지 않는다. 판단 시험용 입력과 지시는 아직 모델 비교를 실행하기 전에 확정했고, 시작 시 별도 manifest로 동결한다.

도중에 스킬 코드, 전체 과제 프롬프트, 채점기 또는 실행 예산을 수정하지 않았다. 별도의 감사 스크립트로 실제 명령 로그와 Gate 상태만 읽었다.
