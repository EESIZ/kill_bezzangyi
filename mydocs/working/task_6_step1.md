# Task 6 — 독립 환경과 계측 준비

사용자의 실행 승인에 따라 Docker 기반 예비 비교를 시작했다. 호스트 전역 스킬·설정은 수정하지 않았다.

## 고정된 실행 조건

- 원본 A: `16671491f6679ad9378f52604d3bc2415b4120c7`, 배포 파일 manifest `e5f41f584bdbe8f469a7c52af3d91bc472c35d064cdc73acfeef9f80430cadf7`.
- 후보 B: 미커밋 구현을 포함한 파일 사본, manifest `5e015fa8d34ce3caffe20f6f486d5a98d90565084bbfd21aec712c08ce9ac911`.
- Linux Docker 이미지: `sha256:a01a516a7e0f915a62fab0317474eac2dbab25210c9de2026a3fc518dd86d74a`.
- Codex CLI `0.155.0-alpha.9.2`, 모델 `gpt-6-astra`, reasoning `low`.
- 매 실행마다 새 컨테이너·작업 폴더·세션. 스킬은 읽기 전용. 호스트 전체 디렉터리나 Docker 소켓을 연결하지 않는다. 인증 파일 하나는 읽기 전용이며 출력 자료에 복사하지 않는다.
- 컨테이너당 CPU 2, 메모리 3 GiB, PID 512, capabilities 제거, no-new-privileges, init 사용. 내부 Codex sandbox는 컨테이너 경계를 사용한다. 중첩 bwrap은 namespace 생성 권한 문제로 동작하지 않아 사전 점검에서 제외했다.
- 각 실행 300초, 부모/후손 합계 200만 토큰. 2초 간격의 영속 사용량 관측으로 한도 초과 시 컨테이너를 중단하고 초과분도 기록한다.
- 8개 작은 Node 과제 × 두 조건 × 2회 = 32회. 과제별 AB/BA를 해시 seed로 정하고 두 번째 반복은 순서를 뒤집는다. 자원 경쟁을 줄이기 위해 순차 실행한다.

## 준비 과정에서 확인한 제약

Claude Code `2.1.263`의 로그인 상태는 로컬에서 true였지만, 실제 모델 요청은 OAuth revoked 401로 실패했다. 따라서 이미 인증 가능한 Codex를 선택했다. Claude Code 전용 자동 Stop hook의 실제 재개 성능은 이번 실행에서 측정하지 않는다.

Codex 사전 점검에서 부모·자식 별도 세션과 누적 토큰 기록을 확인했다. 모든 고유 세션의 마지막 누적 사용량을 더하며 root 최종 합계를 다시 중복 가산하지 않는다. cached_input은 전체 input의 부분집합이다.

첫 컨테이너 회귀에는 init이 없어 종료한 프로세스의 자식 회수 검사가 실패했다. init을 사용한 최종 환경에서는 원본 188/188, 후보 268/268이 통과했다. 실패 로그와 재검사 로그를 모두 보존했다.

## 실험 범위

단일·순차·분기 통합·교차 의존·통합 후 재분기·manifest에서 추가 범위 발견·공유 파일 수정·미완성 파일과 오래된 Gate에서 재개를 시험한다. 추가 범위 발견은 실제 분할이 일어났는지 관측하며 강제로 분할 성공이라고 세지 않는다. 마지막 재개 과제는 정적 중단 fixture이며 실행 도중 프로세스를 강제 종료하는 시험을 대신하지 않는다.

외부 검사는 과제의 공개 인터페이스·필수 모듈·동작 결과를 확인한다. 핵심 동작 검사 8개를 별도의 정답 구현 및 빈 오답 구현으로 점검했다. 작은 단일 과제 계측 리허설은 75.879초, 126089 토큰, 외부 검사 통과였으며 A/B 효과 집계에서 제외한다.

시험 파일·동결 manifest·원본 로그 위치: 현재 작업의 `work/skill-benchmark/`. 실행 시작 전 `e2e-v1-manifest.json`에 프롬프트·채점기·실행기 해시와 순서를 기록했다. 결과가 불리하다는 이유로 실행을 제외하거나 스킬을 도중 수정하지 않는다.
