# Task 2 결과: 기존 unlazy에 배정 계산 도구 연결

## 결과

기존 Kill_bezzangyi 포크에 scripts/schedule.mjs와 scripts/lib/schedule.mjs를 추가했다. 새 스킬·별도 실행 하네스는 생성하지 않았다. 기존 SKILL.md에는 최초 배정, 부모 검증 및 정확한 lease 해제 후, 계획 변경, 재개 시 도구를 호출하는 지침을 연결했다.

- Needs의 직접·간접 선후관계와 Bernstein 읽기/쓰기 충돌 조건을 계산한다.
- 순차 구간, 구조적 분기·합류, 현재 실행 후보와 대기 사유를 반환한다.
- 순차 후속 작업에는 이전 작업과 기록된 native agent handle을 반환해 재사용을 돕는다.
- 현재 실행 중이거나 반환 후 부모 검증을 기다리는 작업은 중복 추천하지 않는다.
- 기존 파일 상태를 매번 읽으므로 재개 시 별도 모델 기억이나 새 상태 저장소가 필요 없다.
- 일반 응답은 대기 사유별 개수로 축약한다. --details에서만 전체 구조와 개별 대기 이유를 반환한다.

## 입력과 사용

기존 .unlazy/<scope>/PLAN.md 및 gates/leaf-<id>.md를 유지한다. ACCESS.json에는 각 작업의 읽는 파일, 비파일 공유 자원, 선언 완료 여부와 계약 버전만 보완한다. 구체적인 형식은 references/scheduling.md에 있다.

```text
node scripts/schedule.mjs --root <작업저장소> --scope <파이프라인> --slots <동시작업수> --details
```

일반 반복에서는 --details를 생략한다. JSON의 launch대로 기존 도구를 호출하고, continuations가 있으면 가능한 경우 앞 작업의 에이전트를 재사용한다. 스크립트는 직접 실행·claim·검증·상태 편집을 하지 않는다.

종료 코드는 정상 조언 0, 검토 필요 1, 잘못되거나 계산 중 변경된 입력 2다. verify-root는 기존 통합·최종 검증을 수행하라는 뜻이며 완료 선언이 아니다.

## 범위와 한계

독립성은 LLM이 선언한 의존관계·접근 범위 안에서만 판정한다. 숨겨진 파일 접근이나 의미 의존성을 자동 발견하지 않는다. 후보는 안정적인 ID 순서로 선택하며 최대 병렬 수나 최소 완료 시간을 보장하지 않는다. 다른 scope의 읽기 정보는 없으므로 다른 scope의 lease가 있으면 검토를 요청한다.

VERIFIED는 기존 드라이버가 부모 재검증과 수동 검토를 수행했다는 의미를 유지한다. 스크립트가 그 실행 이력을 독립적으로 증명하지는 않는다. 현재 snapshot의 조언은 원자적인 실행 허가가 아니며 기존 claim과 dispatch 장벽을 지켜야 한다.

토큰·속도 절감률과 실제 native 에이전트 실행을 포함한 종단 비교는 아직 측정하지 않았다. 이번 결과는 로컬 포크에 반영됐으며 전역 설치본과 훅은 변경하지 않았다.
