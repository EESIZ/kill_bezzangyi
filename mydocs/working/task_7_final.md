# Task 7 — 검증 절차 최소화 재설계 결과

## 완료한 설계

`research/minimal-verification-design.md`에 목표 흐름과 4종 검증의 담당/시점, 기존 규칙 변경표, 현재 증거·무효화, 멱등 사건 처리, native 호스트 경계, 고아 작업·Stop hook 처리, 후속 구현 대상과 평가 기준을 기록했다.

정상 흐름은 계약 확정→제작/개발 테스트→부모 측 공식 검사→다음 작업→실제 통합 검사→최종 요청 대조다. 모든 leaf의 공식 자체 검사와 조상에서의 무조건적인 재귀 재실행을 줄이지만, 부모의 독립 검사·필요한 수동 판단·실제 통합 검사는 유지한다. 현재 검사 지문만으로는 산출물 신선도를 보장하지 못하므로 새 증거 맥락을 구현하기 전 기존 --reverify를 생략해서는 안 된다.

## 검산

상위 작업의 `work/minimal-verification/design-check.mjs`에서 정책 모델 28개 시나리오를 검산했다. 독립 작업 4개의 모든 반환 순서 24가지에서 같은 의무의 공식 검사가 반복되지 않았다. 모델상 지역 검사 4회+통합 검사 1회, 관련 부품 변경 시 해당 지역+통합 재실행으로 7회가 됐다. 비교 예시의 기존 13회는 4개 지역 검사가 자체·부모·직접 branch에서 각각 실행된다는 조건부 수치다.

중복 사건·동일 ID 다른 요청·재시작·입력/계약/검사기/환경 변경·수동 증거 변경·검사 실패·동시 변경·미승인 검사·미해결 보고/lease/attempt/journal·고아/abandon·최종 요청 대조 누락을 다뤘다. 실제 프로세스 종료·저장 원자성·native 실행·적대적 위조·품질 동등성·토큰 절감의 검증은 아니다.

## 적용 상태

이번 사용자 요청 범위인 재설계와 검산을 완료했다. `SKILL.md`, 실행기, templates, 현재 Gate 의미와 전역 설치는 변경하지 않았다. 기존 작업 변경분은 보존했다. 코드가 바뀌지 않아 전체 제품 회귀 검사를 다시 실행하지 않았고, 설계 모델 검산과 문서 공백 검사를 수행했다. 후속 구현 범위는 설계 문서 11절에 명시했다.
