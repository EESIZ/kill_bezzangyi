# Task 8 — 기존 A/B와 새 C 비교 완료

## 실행과 결과

사용자 요청대로 기존 A/B 데이터와 보고서를 보존하고, 동일 과제/프롬프트/채점기/이미지/모델 설정으로 C 전체 작업 16회와 판단 16회를 추가했다. 모든 실행의 사용량 기록이 있고 시간 초과·교체 실행 없이 32/32 관측 검사를 통과했다.

| 구간 | A 총토큰 | B 총토큰 | C 총토큰 | C/A | C/B |
|---|---:|---:|---:|---:|---:|
| 전체 작업 | 2,102,705 | 3,786,015 | 3,776,383 | +79.6% | −0.25% |
| 배정 판단 | 1,423,441 | 1,466,512 | 805,812 | −43.4% | −45.1% |

전체 작업 평균 시간은 A 88.2초, B 99.4초, C 96.4초다. 판단 평균은 A 24.8초, B 24.2초, C 16.6초다. 판단의 비캐시 입력은 C 124,073으로 B 대비 29.6% 감소했다.

## 실제 동작과 해석

- C 전체 과제 16/16에서 verify-once를 사용했고, 종료 후 별도 읽기 전용 증거 감사 16/16을 통과했다.
- C 판단 16/16은 shell 명령 2개(스킬 읽기, 스케줄러 실행)로 진행했다. 내부 소스 추가 읽기는 관측되지 않았다. shell 명령 수를 모델 추론 호출 수와 동일시하지 않는다.
- 전체 작업은 A 16세션, B 20세션, C 22세션이었다. C forkjoin은 한 반복에서만 자식 둘을 사용했고, discovery는 두 반복 모두 자식 둘을 사용했다. 전체 절감은 배정 전략 변동과 분업 비용에 상쇄됐다.
- 같은 discovery 유형에서 B 평균 996,103토큰→C 753,113토큰으로 줄었지만, 이를 전체 과제의 일반적 개선으로 확대하지 않는다.
- 종료 기록에서 미충족/abandon/파싱 오류, pending report/journal, 미완료 PLAN/wave, 남은 lease가 모두 0이었다.

## 검증·보존

사전 Linux 회귀 282/282. 실행 전에 C 49개 파일과 실험 소스를 동결했다. A/B 원자료와 manifest, A/B/C 동결 패킷, C 실행 코드·과제·채점기 해시를 확인했다. 최종 CSV 96행의 6개 조건 합계를 PowerShell로 독립 계산해 JSON 합계와 대조했다.

사후 감사 초기에 기본 Docker PATH가 실제 Codex PATH와 달라 거부됐으므로, 실행 로그와 Gate의 경로 지문으로 확인한 PATH를 같은 이미지에 재현했다. 그 후 전체 맥락 검사를 통과했다. 과제 파일/receipt/동결본/원래 채점을 변경하지 않았다. 상세는 C 자료의 audit-environment-check.md에 있다.

## 범위와 한계

C는 A/B보다 나중에 실행한 후행 비교이며 무작위 교차 실행이 아니다. 유형당 반복 2개라 작은 차이를 일반적 우위로 주장하지 않는다. 기존 기능 검사 통과는 품질 동등성·숨은 결함 부재의 증명이 아니다. 가격 환산과 실제 청구액 비교는 하지 않았다.

증거 재사용은 명시된 닫힌 입력/정지 조건을 전제로 한다. 전체 advance 사건 실행기, native 호출 자동화, OS 정지 증명, 자동 Claude Stop hook은 이번 구현/실험 범위가 아니다. 루프의 모든 모델 호출이 없어진 것은 아니다. 설치된 전역 스킬·훅을 변경하거나 GitHub에 push하지 않았다.
