# Task 3: 멱등적인 구조 변환과 독립 검산

사용자가 규칙을 스크립트로 구현하고 멱등성·설계를 검증한 뒤 완성 결과를 보고하도록 승인했다. 기존 배정 테스트 19/19 통과를 기준선으로 확인했다.

1. 불변조건과 입력/변환/복구 계약을 확정한다.
2. 재귀 분할·보수적 병합 계산기와 별도의 구조/배정 검산기를 구현한다.
3. 명시적인 operation ID와 재실행 가능한 저널로 파일 반영을 멱등적으로 만들고 구조 Gate를 연결한다.
4. 중단/재시도/중복/고아/낡은 증거/재분기 실패 사례를 검증한다.
5. 기존 전체 회귀와 사용 문서·최종 보고를 완료한다.

## 설계 계약

- 기존 실행 하네스와 Gate/Stop hook 구현은 유지한다. 새 스킬 생성·전역 설치 없음.
- structure.mjs plan/apply/recover는 기존 PLAN·ACCESS·Gate를 사용한다. 구조 메타데이터만 STRUCTURE.json에 둔다.
- 요청은 schema, operation(명시적인 멱등 키), contractRevision, refinements다. 자식은 id/needs/ledger/access/tier 및 선택적 refinement를 갖는다. 부모의 원래 Gate와 ID를 통합 작업으로 보존한다.
- 실행 기록이나 lease를 가진 부모는 자동 전환하지 않는다. 아직 시작하지 않은 부모만 펼친다. 미지원 전환은 실패로 명확히 반환한다.
- 모든 자식의 쓰기/외부 읽기 범위는 부모의 선언 범위를 벗어나지 않아야 한다. 범위 확장은 먼저 명시적인 계획 변경이 필요하다.
- 병합은 같은 원래 작업 ID 집합의 partition 변경이다. Gate와 개별 작업 완료 시점은 보존한다. 실행/lease 중인 묶음은 병합하지 않는다.
- 검산기는 계산기의 추천을 호출해 정답으로 사용하지 않고, 작업 보존·중복·간선·Gate·그룹 비순환성·남은 순차성·선택 작업 충돌을 별도로 검사한다.
- plan과 check는 읽기 전용이다. apply는 기존 root/branch Gate의 PASS를 먼저 무효화하고, 준비된 저널을 저장한 뒤 PLAN/ACCESS/leaf/STRUCTURE 파일을 반영한다. 저널이 남으면 scheduler와 구조 Gate는 실행/완료를 허용하지 않는다.
- 재시도는 동일 operation+동일 요청이면 이전 적용 결과를 반환하며 파일을 다시 쓰지 않는다. 같은 operation에 다른 요청은 거절한다.
- 중단 복구는 저널의 before/after 어느 쪽과도 일치하지 않는 파일을 덮어쓰지 않는다. 자동 롤백·Gate 복원·에이전트 재실행은 하지 않는다.
- 검산 성공과 완료 성공을 구분한다. --final은 실제 Gate·상태·dispatch·lease·인계를 확인한다. 기존 Stop hook의 무진전 인계는 성공으로 바꾸지 않는다.
- managed 변경은 Gate를 무효화하지만 외부에서 임의로 파일을 바꾸는 모든 경로를 차단할 수는 없다. 기존 --reverify 및 변경 후 재검산을 스킬 지침으로 유지한다.

## 검증 항목

반복 계산 동일성, 동일 작업 재적용 무변경, 다른 payload 멱등 키 재사용 거절, 재귀 분할, 병합 고정점, 부모 Gate 보존, orphan/중복/간선 누락/잘못된 병렬 선택 검출, 검증 전 부모 완료 거절, 실행 중 부모 변환 거절, 중단 후 roll-forward, 복구 중 외부 편집 보존, 재개 중복 실행 방지, root Gate를 통한 Stop hook 차단, 기존 전체 테스트.
