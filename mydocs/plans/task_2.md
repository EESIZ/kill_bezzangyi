# Task 2: 기존 스킬에 결정론적 배정 계산 연결

사용자는 기존 unlazy 파생 스킬을 유지하고 판단 시점에 계산 스크립트를 호출하는 계획을 승인했다. 새 스킬 생성, 별도 실행 하네스, 전역 설치는 범위 밖이다.

1. PLAN·Gate를 권위 있는 입력으로 유지하고, 읽기 대상·공유 자원만 ACCESS.json으로 보완한다.
2. 선후관계와 Bernstein 읽기/쓰기 조건으로 순차 구간, 독립 분기, 현재 실행 후보를 산출하는 읽기 전용 도구를 구현한다.
3. 최초 배정, 부모 검증·lease 해제 후, 계획 변경, 재개 시 호출하도록 기존 스킬에 연결한다. 명령 승인·부모 검증·통합·Stop hook은 유지한다.
4. 순차/분기/합류/재분기, 충돌, 불완전한 입력, 재개와 기존 기능의 회귀를 검증하고 결과를 기록한다.

## 구현 계약

- Node.js 16+, 외부 의존성 없음. 스크립트는 에이전트 실행·검사 실행·상태 변경을 하지 않는다.
- 실행은 LLM이 기존 native 도구로 수행한다. 계산 결과는 현재 파일 스냅샷에만 유효하며 실제 claim이 최종 소유권 경계다.
- `Needs`는 PLAN, 쓰기 파일은 Gate의 OWNS, 상태는 PLAN 및 기존 dispatch·lease 기록을 사용한다. READS와 비파일 자원만 보조 선언한다.
- 순차 연결은 의존 DAG의 단일 후속/단일 선행 구간으로 묶는다. 묶음은 같은 에이전트 재사용 권고이며 개별 Gate나 부모 검증을 합치거나 생략하지 않는다.
- 병렬 판정은 충돌이 없음을 보수적으로 증명할 수 있는 경우에만 인정한다. ID 순서 greedy 선택으로 재현성을 확보하며 최대 병렬 수 최적화라고 주장하지 않는다.
- 정상 출력은 간결한 JSON. 선택 작업, 대기 이유, 남은 상태 및 구조 요약만 반환하고 상세 구조는 선택 옵션으로 반환한다.
- Gate 통과는 현재 증거 확인에 한정된다. 부모 검증과 수동 검토는 기존 State 의미대로 드라이버 책임이다. 전체 완료 판정은 기존 root 검증·Stop hook에 맡긴다.

## 완료 조건

- 결정론적 배정 테스트와 기존 전체 회귀 검사 통과.
- 기존 gate-check, dispatch-check, stop-hook 및 공용 구현 파일 변경 없음.
- 같은 입력에서 같은 결과, 재개 시 이미 실행 중인 작업의 중복 추천 없음.
- 실측 없이 토큰·시간 절감률 주장 없음.
